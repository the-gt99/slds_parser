# Раздача фотографий товаров через CDN

Включена на slamdunk.shop 11 сентября 2026 года. WordPress DB, локальные фотографии и S3-объекты при переключении не изменялись.

## Устройство

- Индекс: `/var/www/u0347517/data/media-cdn/products.sqlite3`, вне webroot, root:u0347517, 0640.
- В индексе 4 969 887 путей из manifest со статусом `uploaded_verified`, ключами `products/` и исходным путём внутри production uploads.
- Общий resolver: `wp-content/mu-plugins/slds-media-cdn/runtime.php`.
- WordPress-фильтры: `wp-content/mu-plugins/slds-cdn-canary.php` (сохранено прежнее имя подключения).
- Standalone-фронт: подключение resolver в `wp-content/themes/slds/custom_index.php`.
- Прежний вызов в `single_product/prepare_images.php` подключает совместимый shim `single_product/cdn-canary.php`.
- Индекс читается через SQLite3 в PHP 7.4, обслуживающем сайт. Для CLI-проверок использовать `/opt/php74/bin/php`.

Resolver проверяет точный путь, размер и mtime локального файла. Неизвестные, отсутствующие или изменившиеся после выгрузки файлы продолжают использовать исходный URL. Полная карта не загружается в память PHP: используется индексированный запрос и небольшой кеш на один запрос страницы.

Для добавления публичных изображений других разделов сборщик индекса поддерживает `--all-categories`. Название serving-файла `products.sqlite3` сохранено для совместимости; состав определяется данными индекса. Общий uploader поддерживает `products`, `categories`, `brands`, `banners`, `content` и переиспользует подтверждённый объект по хешу независимо от категории. Не следует выгружать весь uploads без определения публичного назначения файлов.

Актуальная дополнительная выгрузка использует `pending-audit-20260911-110406/upload.list` для товаров и `public-upload-plan.json` для остальных публичных изображений. Источники второго списка: опубликованные страницы/статьи, метаданные таксономий, публичные настройки темы и ссылки на uploads в шаблонах. `activate-complete-media-index.py` проверяет результаты задач и каждый путь перед обновлением индекса; отчёт сохраняется в `complete-media-activation.json`. Предыдущий индекс сохраняется рядом как `products-before-*.sqlite3`.

Дополнение 11 сентября: проверены и добавлены все 63 861 пути из дополнительных списков (6 913 товарных, 56 825 контентных и 123 изображения категорий). 1 010 путей переиспользовали существующие объекты. Индекс после дополнения содержит 5 033 748 путей. Неподтверждённых файлов в этих списках не осталось.

В `functions.php` шесть существовавших регулярных выражений нормализации домена теперь сохраняют `cdn.slamdunk.shop`. Иначе последующий WordPress-фильтр атрибутов изображения превращал CDN-URL в ошибочный `https://slamdunk.shop/content/...` и ломал миниатюры блога. Остальные изменения пользователя в файле сохранены; исходник и hashes лежат в `media-migration/theme-cdn-host-*`. После исправления проверены реальная отрисовка WordPress-вложения и загрузка 29 CDN-изображений статьи в браузере.

Ссылки подменяются при формировании ответа, включая HTML и JSON каталога. Старые записи БД остаются источником идентичности вложений. Полная новая выгрузка или delta при этом не запускается.

В `standalone_catalog/lib/http-cache.php` дата последнего изменения ограничена снизу датой индекса, чтобы браузер получил новую страницу после переключения. Все существовавшие изменения в этом файле сохранены побайтово.

## Alt фотографий товаров

11 сентября добавлено формирование alt из исходного имени файла без расширения. Дефисы, регистр и номера сохранены. HTML галереи обрабатывается до подмены URL; WordPress использует `_wp_attached_file`, каталог формирует alt в PHP и JavaScript. Обратный поиск по хешу не используется: одинаковый файл может иметь разные исходные имена.

База данных, объекты S3 и локальные фотографии не менялись. Копии кода перед установкой: `media-migration/product-alts-backup-*` (runtime, plugin, prepare_images.php, cards.php) и `media-migration/catalog-alt-*.js`. Для отката сверить последующие изменения и восстановить только затронутый код из этих копий.

Исправлена выявленная при проверке ошибка регулярного выражения на большом HTML каталога; добавлен тест на 2,5 МБ встроенного script. После исправления каталог отвечает 200. На свежей странице каталога проверены 307 товарных изображений без пустого alt, на карточке товара — 108; проверен JavaScript-рендер. Старые закешированные страницы могут показывать прежний alt до обновления HTML.

## Откат

Снимок исходных файлов и hashes находится в каталоге `cdn-rollout-*` внутри `/var/www/u0347517/data/media-migration/` (создан 11 сентября). Установочный скрипт сохранил содержимое файлов непосредственно перед изменением, включая незакоммиченные правки.

`rollback-wordpress-cdn.py <точный путь снимка>` восстанавливает файлы только если после установки они не изменялись. При несовпадении hash нужно разобрать последующие изменения вручную. Фотографии и индекс скрипт не удаляет.

Перед будущим удалением локальных фотографий необходимо отдельно изменить проверку локального stat в resolver, проверить полноту карты и новые загрузки. С текущей проверкой отсутствие локального файла оставляет исходный URL. Удаление файлов этой задачей не разрешалось и не выполнялось.
