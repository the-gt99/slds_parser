# Проверка обновлений и переводов

## Обновление цен и наличия

`GET /api/inventory-health` возвращает 200 только при работающем обновлении без failed-позиций и проверок старше 25 часов. Иначе возвращает 503 и счётчики `products`, `overdue`, `failed`, `lastCheckedAt`. Это отдельная проверка от `/api/health`, который проверяет доступность приложения. Внешние уведомления пока не подключены.

Дополнение существующего полного снимка выполняется заданиями `sync_wordpress_catalog` с `mode: inventory`. Источник списка — подтверждённые `target_products` со статусом `synced`. Перед подключением каждой карточки проверяется её текущий идентификатор WordPress. Задание не меняет курсор полного каталога и не запускает полный аудит или экспорт карточки. Несовпадение идентификатора блокирует соответствующую страницу и требует расследования.

Зависшие позиции без активного задания восстанавливаются после 30 минут. Для уже отправленного WordPress-задания повторяется только опрос результата. Discovery в цикле обновления не ставит новые товары на сбор.

## Перевод через OpenRouter

Настройки: `PARSER_TRANSLATION_PROVIDER=openrouter`, `PARSER_OPENROUTER_API_KEY`, `PARSER_OPENROUTER_MODEL=deepseek/deepseek-v3.2`. Ключ хранится только в серверном окружении. Провайдер включается явно, переключения на другой переводчик при ошибке нет. Ответ с незавершённым переводом отклоняется; HTTP 402 не повторяется. Журнал `translation_usage` содержит токены и стоимость ответа без исходного текста и ключа.

Для обработки только записей без подтверждённого провайдера используйте `RETRANSLATION_SCOPE=missing-provider`. CLI `enqueue-retranslation` по умолчанию выполняет расчёт без постановки заданий; применение требует `RETRANSLATION_APPLY=true`, размер партии задаёт `RETRANSLATION_LIMIT`. Режим `outdated` сохраняет прежнее поведение выбора всех записей с иной идентичностью перевода.

При переходе между провайдерами WordPress может принимать дополнительные точные идентичности через `target.config.acceptedTranslations`: массив объектов с полями `providerCode`, `providerVersion`, `sourceLocale`, `targetLocale`. Основной `requiredTranslation` остаётся обязательным; локали дополнительных записей должны совпадать. Для модели по умолчанию версия провайдера — `1.0.0:deepseek/deepseek-v3.2`. Перевод без идентичности не становится подтверждённым автоматически.

Перед массовым переводом требуется ограниченный запуск с проверкой качества, фактической стоимости и итогового preflight. Перед следующими этапами отдельно проверяются неразрешённые классификации и точные размерные сетки.
