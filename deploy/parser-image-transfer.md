# Перенос старых изображений парсера

Административная команда `dist/src/cli/transfer-legacy-images.js` переносит только готовые WebP из настроенного каталога изображений. Обычная публикация S3 остаётся неизменной: новые изображения имеют контрольную сумму в имени.

Старые файлы сохраняют исходный ключ `parser/<source>/item_<id>/<name>.webp`. Существующий объект не перезаписывается: отсутствие проверяется чтением, новая запись использует `IfNoneMatch: *`. Перед удалением локального файла проверяются SHA-256 объекта S3 и реально отданного CDN содержимого, затем повторно проверяется исходный файл. При несовпадении, изменении файла или ошибке он остаётся локально.

Конфигурация Nginx `deploy/nginx/slds-parser-images.conf` сохраняет локальную раздачу для ещё не перенесённых файлов. Отсутствующие готовые WebP по старым `/images/` адресам перенаправляются на тот же ключ CDN. Иные отсутствующие пути получают 404. Установка конфигурации и проверка `nginx -t` обязательны до первого удаления. База товаров и WordPress не переписываются.

Сервис `slds-parser-image-transfer.service` работает от пользователя приложения в одном процессе, с шестью одновременными переносами, низким CPU/I/O приоритетом и паузой 50 мс между порциями. CPU ограничен половиной одного ядра, память — 768 МБ с учётом параллельной проверки содержимого. Он не запускает перевод, скачивание с источника или экспорт. Файлы моложе 24 часов и промежуточные форматы не трогает. После пяти последовательных ошибок останавливается без автоматического перезапуска, дождавшись завершения текущей порции. Отдельные неуспешные файлы остаются локально; дубли путей в порции запрещены.

Параметры: `IMAGE_TRANSFER_CONCURRENCY` (по умолчанию 1, допустимо 1–96), `IMAGE_TRANSFER_DELAY_MS`, `IMAGE_TRANSFER_MINIMUM_AGE_HOURS`, `IMAGE_TRANSFER_LIMIT`, `IMAGE_TRANSFER_RELATIVE_PATH` (для точечного smoke), `IMAGE_TRANSFER_CHECKPOINT`. Стандартный отчёт: `legacy-image-transfer.json` рядом с каталогом изображений, обновляется каждые 15 секунд и при завершении. Счётчики относятся к текущему запуску, полный проход заранее не сканируется. При незавершённом checkpoint обход начинается с каталога `lastPath`, после его конца возвращается к предыдущим каталогам: ранние ошибки и оставшиеся файлы не исключаются. Удалённых файлов уже нет, оставшиеся объекты проверяются идемпотентно. Повреждённый checkpoint или отсутствующий каталог требуют проверки оператором, автоматического пропуска нет.

Порция ограничена одновременно числом файлов и суммой локальных размеров 64 МиБ; для крупных файлов фактическая параллельность будет ниже заданной. S3-клиент допускает до 96 keep-alive соединений. Значения выше штатных шести предназначены для контролируемого временного переноса с отдельным замером нагрузки, ошибок и пропускной способности. Остановленные на время переноса воркеры и таймеры необходимо восстановить по исходному состоянию, в том числе при аварийном завершении.

Остановка: `systemctl stop slds-parser-image-transfer.service`. Удалённые локальные копии восстанавливаются из S3 по сохранённым ключам. До восстановления локальных копий нельзя отключать перенаправление старых URL.
